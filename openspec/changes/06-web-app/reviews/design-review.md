## Design review: 06-web-app

Intent: deliver a bilingual, accessible Angular client for activities, reports, account settings and OAuth consent.

Scope: the untracked `apps/web`, the change artifacts and `docs/web-design.md`; unrelated changes were excluded. Paths below are relative to the repository root. The codebase-memory service reports this repository is not indexed; impact and negative searches were therefore manual. The frontend is deliberately layered by project rule; the generic backend layered model is otherwise N/A. Commit hygiene is N/A for uncommitted work.

### Findings (most severe first)

- **[must-fix][architecture] Consent security policy lives in the controller** — `apps/web/src/app/features/consent/consent-page.ts:74`: `safeRedirect` contains security decisions in a component, contrary to `docs/agent-rules.md:11`. It accepts `https://evil.example/anything` when the displayed destination is `https://client.test/return`, because it compares only scheme and a nonempty host; the same weakness affects custom schemes. The current API constructs its response from the stored destination (`apps/api/src/oauth/oauth-authorization.service.ts:205`), so this is a missing defense against an inconsistent or compromised response, not a demonstrated normal-path exploit. Move validation to a service and compare scheme, authority and path against the actual displayed URI while permitting the API's added OAuth query parameters; test different host, port, path and scheme.
- **[must-fix][bad practices] Application initializer loses its injection context** — `apps/web/src/app/app.config.ts:24`: after `await inject(ConfigService).load()`, the calls to `inject(AuthService)` and later dependencies run outside Angular's synchronous injection context. Bootstrap rejects with NG0203 before the application renders, even when config loads successfully. Capture all dependencies synchronously before the first await and add a real application-initializer bootstrap test. A successful compilation does not execute bootstrap.
- **[must-fix][bad practices] Consent framing headers are only an example** — `apps/web/public/_headers.example:1` and `apps/web/README.md:22`: these files instruct a future server to set CSP and X-Frame-Options but do not configure response headers. `consent-page.ts:29` hides controls in a frame after JavaScript executes; it cannot make the browser refuse to render the response as the spec requires. Supply enforceable deployment configuration and verify actual document response headers; the phase-07 deployment dependency must be completed before this requirement is marked done. The frontend guard is a useful additional defense, not a substitute.
- **[must-fix][bad practices] Quick-add can create duplicates and erase newer input** — `apps/web/src/app/features/activities/activities-quick-add.html:4`, `apps/web/src/app/features/activities/activities-quick-add.ts:27`, `apps/web/src/app/features/activities/activities-page.ts:83`: Enter and submit remain enabled during the create request; repeated gestures send concurrent POSTs, and a late success unconditionally resets whatever the user has since typed. Track pending creation, prevent duplicate submissions and preserve edits made after the submitted snapshot; test with deferred responses.
- **[should-fix][bad practices] Activity results race when filters or pages change** — `apps/web/src/app/features/activities/activities-page.ts:47`: each `load` independently subscribes and writes `items`, `groups`, `loading` and errors. An older slow response can overwrite the newest page or filter and clear its loading state. Use a cancellable latest-request stream or a request generation check, including destruction cleanup; test out-of-order responses.
- **[should-fix][bad practices] Registration loses the pending consent request** — `apps/web/src/app/features/auth/login-page.html:22`, `apps/web/src/app/features/auth/register-page.html:27`: switching between login and registration drops `returnUrl`, so an agent user choosing registration is sent to activities instead of the consent request. Preserve the query parameter in both links and test guard → login → register → consent.
- **[should-fix][bad practices] Return URLs lack an explicit local-path policy** — `apps/web/src/app/features/auth/login-page.ts:36`, `apps/web/src/app/features/auth/register-page.ts:36`: untrusted query text is passed directly to Angular `navigateByUrl`. Angular's router handles this as an internal URL tree, so an external browser redirect is not established by this code; nevertheless it does not implement the requested explicit same-origin relative-path restriction. Validate a leading single slash, reject protocol-relative URLs, backslashes and absolute URLs, then navigate to a safe fallback. Test both pages and malicious encodings.
- **[should-fix][bad practices] Language save errors and concurrent changes are unhandled** — `apps/web/src/app/shared/language-switcher.ts:20`, `apps/web/src/app/core/services/auth.service.ts:53`: the UI changes immediately and discards the profile update promise. A failed request yields no feedback or rollback, and concurrent responses can overwrite the latest choice in user state. Serialize or cancel changes, handle failures visibly, and reconcile with the API source of truth. The settings date pipes at `apps/web/src/app/features/settings/api-keys-section.html:27` and `apps/web/src/app/features/settings/connected-apps-section.html:12` also use Angular's default locale rather than the active language; bind the selected locale and test live switching.
- **[should-fix][bad practices] Live announcements and motion exceed the brief** — `apps/web/src/app/features/activities/activity-list.html:1` makes the entire changing activity list an atomic polite live region, causing all titles and links to be reread after updates; `apps/web/src/app/features/activities/activities-page.ts:81` forces smooth scrolling despite reduced-motion preference. Announce only a concise result count/status and use instant scrolling when reduced motion is requested. `apps/web/src/app/shared/app-button.css:41` slows rather than disables the spinner animation; provide a static reduced-motion state.
- **[should-fix][tests] Scenario tests do not prove end-to-end behavior** — `apps/web/src/app/features/activities/activities-page.spec.ts:51` checks service arguments and reload count, not that three URLs survive and the new activity appears; `apps/web/src/app/features/consent/consent-page.spec.ts:38` calls `decide` directly with fake services, not actual button-to-API behavior; `apps/web/src/app/features/reports/report-result.spec.ts:9` mocks the renderer to return safe HTML. Add focused integration tests through actual components and services, including real sanitization into the DOM, genuine button clicks, translations and asynchronous failure/race cases. Tests should use the exact OpenSpec scenario names (`docs/agent-rules.md:27`); many currently use approximate names.
- **[should-fix][tests] Coverage gate omits controllers and bootstrap** — `apps/web/angular.json:71` includes only services and repositories. Its passing 80% gate cannot establish the required controller line and branch coverage (`docs/agent-rules.md:28`), and the initializer is not exercised. Include page/controller files and bootstrap in coverage and enforce the specified thresholds.
- **[should-fix][formatting] Prettier check fails** — `apps/web/src/app/app.config.ts:12` is one example; `npx prettier --check 'src/**/*.{ts,html,css}'` reports 180 files. Run the configured Prettier on the change after review, following the project's formatting workflow.

### Security, accessibility and lifecycle observations

- Markdown flows through `marked.parse`, then `DomSanitizer.sanitize(SecurityContext.HTML, ...)`, then Angular's `[innerHTML]` binding (`apps/web/src/app/core/services/reports.service.ts:104`, `apps/web/src/app/features/reports/report-result.html:7`); no `bypassSecurityTrust*` was found. The service test uses the real sanitizer for script, handler and JavaScript link input (`reports.service.spec.ts:86`), but the component test mocks it. Ordinary Markdown images can make remote requests, and links remain navigable; the review did not establish an XSS bypass. Activity links explicitly use `target="_blank" rel="noopener noreferrer"` (`activity-item.html:24`); rendered Markdown receives no added target or rel policy, so test rendered raw links and images in a browser and choose a deliberate remote-image policy.
- JWT is intentionally persisted in localStorage per the design (`auth.service.ts:9`); it remains readable by any successful same-origin XSS. No secret logging was found in `apps/web/src`. Blocked storage is caught and leaves an in-memory session (`auth.service.ts:18`), but reload cannot restore it; blocked storage also prevents job resumption (`reports-page.ts:99`). API key plaintext is held in the settings component signal and cleared on dismissal (`settings-page.ts:39`, `:98`), with no persistence found. Clipboard use requires a user action; settings catches clipboard failures (`settings-page.ts:70`), and reports have a fallback (`reports.service.ts:109`).
- Consent displays the unverified name, ID, full redirect and full-access text (`consent-details.html:2`, `consent-page.html:8`); the only normal decision triggers are button clicks (`consent-page.html:10`–`14`), with no automatic approval found. The retry repeats the prior user decision. The JavaScript frame check and headers limitation are described above.
- Native confirmation dialogs use `showModal`, focus the safe action and restore focus (`shared/confirm.service.ts:20`); the activity dialog also restores focus (`activity-form-dialog.ts:34`, `:63`). Native modal focus behavior and keyboard interaction were not browser-tested. Main pages have a page header `<h1>`, with day and section headings below; consent uses a single `<h1>`. Labels are generally associated; individual browser/screen-reader behavior remains unverified.
- All requested color combinations from `apps/web/src/styles/tokens.css:2` pass WCAG AA normal-text 4.5:1: text/background **14.81**, text/surface **15.73**, muted/background **5.37**, muted/surface **5.70**, accent/background **5.34**, accent/surface **5.67**, danger/background **5.14**, danger/surface **5.46**. No listed pair fails; ratios do not assess opacity, focus rings, button text or every actual CSS combination.
- Recursive key comparison found identical Spanish/English keys in root, activities, reports, consent and settings. Language names and the Taskory brand are literal; these appear intentional proper/endonym labels, rather than untranslated explanatory text. The active language updates document `lang` (`app.config.ts:30`, `language-switcher.ts:24`). Activity dates use `Intl.DateTimeFormat` with the active language (`activity-list.ts:23`); settings dates do not, as noted above. Numeric interpolations such as `report-result.html:6` are not locale-formatted.
- Polling uses a cancellable RxJS subscription and unsubscribes on destruction (`reports-page.ts:46`, `:116`); test scheduler coverage exists (`reports.service.spec.ts:54`). Ordinary one-shot requests are not generally canceled when pages are destroyed, and quick-add and list races are covered in findings. An HTTP observable normally completes, so this alone is not evidence of a permanent leak.

### Done well

- Components do not inject `HttpClient`; API access is concentrated in repositories, with the separate Transloco loader fetching translation resources.
- The application separates feature views from shared controls, and report polling has deterministic scheduler tests and explicit cancellation.
